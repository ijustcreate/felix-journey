Case study 03 · Complex defect isolation

The calendar was haunted by preserved data.

A Project Lantern regression where inactive legacy records remained historically correct—and visually destructive.

Initial symptom

A layout problem with a data-history cause.

The new Welcome Gallery and Discovery Hall schedule tracks were compressed because archived full-day seed events still occupied visible calendar lanes.

The records were not supposed to be deleted. They were legacy defaults preserved in storage with active=false. The failure was subtler: preservation state had leaked into presentation eligibility. The system remembered correctly and displayed incorrectly—the software equivalent of keeping your ex’s toothbrush for legal reasons, then assigning it half the bathroom.

User impact

Current operating events became narrow and hard to read.

Risk

A broad cleanup could erase historical or customized schedule data.

Constraint

Only two exact obsolete seed records should be archived from visible lanes.

Quality bar

Migration must remain stable on repeated normalization.

Investigation path

Preserve the record. Remove its visual consequence.

01

Reframe the report

Not “calendar columns are too narrow,” but “inactive migrated records still participate in visible lane allocation.”

02

Protect the dangerous constraint

Do not delete or broadly filter user schedules. Match the two exact legacy seed IDs and preserve their stored records.

03

Separate domain state from view state

An archived record remains part of history while becoming ineligible for the active calendar projection.

04

Verify migration behavior

Confirm custom schedules survive, exact legacy records remain inactive, a second normalization adds no duplicates, and no ghost events render.

05

Verify the human consequence

Measure restored lane width and readability instead of declaring victory because a unit test turned green.
